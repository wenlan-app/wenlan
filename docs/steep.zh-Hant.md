# Steep（沉澱）：讓知識持續可用

[English](steep.md) · [繁體中文](steep.zh-Hant.md) · [回到 README](../README.zh-Hant.md#持續更新知識並保留歷史)

沉澱（Steep）是文瀾讓知識持續可用的整套流程。新素材、來源變更或你提出的整理目標，都可能需要更新相關記憶、筆記、資料夾、主題與關係；實際更新哪些，依據需求而定。來源、審核保護與歷史紀錄都會一併保留，讓後續工作能延續先前累積的理解。

使用者只需選一個入口：`/wenlan steep`（Codex 中為 `$wenlan steep`）。在 `/wenlan` 後說明你要整理什麼，前門會把完整要求交給沉澱。沉澱會查看相關現有資料，再處理需要的部分。即使沒有新素材或待更新筆記，明確提出的重整要求仍可執行；一般整理不需每次另外確認計畫。

```text
新素材 / 來源變更 / 你提出整理目標
                    |
                    v
                沉澱（Steep）
                    |
    +-- 記憶：加入已確認的新發現，或保留更正脈絡
    +-- 筆記：視需要建立、補充、更新、合併或重建
    +-- 資料夾：需要改善分類或導覽時才調整
    +-- 主題：依有依據的內容建立或更新
    `-- 關係：依來源建立；衝突時保留既有審核保護
                    |
                    v
             保留來源、審核規則與歷史
```

「隨叫」由連接的 AI 工具處理你提出的工作。「自動」則以已設定的模型處理符合條件的背景工作；它不會自行推測並執行你未提出的整理目標。兩種模式的觸發方式和檢查不同，詳見[執行時機](#什麼時候執行)與[如何使用沉澱](#啟用沉澱與檢查結果)。

簡短的沉澱入口會依需求載入其中一項操作說明：[新素材](../plugin/skills/steep/references/new-material.md)、[來源變更](../plugin/skills/steep/references/refresh-pages.md)、[依目標整理](../plugin/skills/steep/references/reshape-knowledge.md)或[明確重建單篇筆記](../plugin/skills/steep/references/rebuild-pages.md)。只載入當下需要的說明。合成、分群、合併與重建都是沉澱內部操作；`/wenlan distill` 不再是獨立流程。

## Memory lifecycle：保存與修正單筆發現

一筆記憶保存一個決定、心得、偏好或事實，可以單獨找回，不必先整理成頁面。

| 階段 | 會發生什麼 |
|---|---|
| **保存** | 留下完整、可獨立理解的發現，以及已有的來源脈絡。 |
| **分類與補充** | 透過指定模型補上類型、結構化資訊與搜尋線索；呼叫端明確指定的類型仍優先保留。 |
| **建立關聯** | 啟用整理後，依別名、名稱或相似度比對人物、專案與概念，讓不同資料的記憶連到同一實體，並保留各自來源。 |
| **修正或調解** | 明確取代時，以 `supersedes` 連結新舊記憶。模型驅動的衝突調解為選配，預設關閉。 |

較新的文件不會直接取代舊記憶。取代生效後，舊記憶會依模式從一般檢索隱藏，或以封存狀態保留可見；新舊取代關係仍保留。詳見[記憶的審核規則](knowledge-guide.zh-Hant.md#原子記憶)。

## Page lifecycle：維護可編輯的知識頁

知識頁把相關來源與記憶整理成帶引用的 Markdown，供你閱讀、編輯。你可以在 App 撰寫、請 AI 撰寫，也可以在需要時由沉澱合成累積資料；建立新筆記不必先執行另一項指令。

| 階段 | 會發生什麼 |
|---|---|
| **撰寫或合成** | 保存頁面，或由已設定的頁面合成模型整理符合條件的相關資料；不是每次匯入都會產生頁面。 |
| **引用與追蹤** | 記錄支持頁面的來源與記憶，讓依據變動時能標記相關頁面待更新。 |
| **重新整理** | 依目前依據重建符合條件的頁面，並檢查引用。 |
| **套用或待審** | 直接更新 AI 維護的頁面，或依頁面歸屬與審核鎖定產生待審修訂；具體界線見下節。 |
| **保留歷史** | 保留一定範圍的頁面變更紀錄，與記憶之間的取代關係分開追蹤。 |

**新發現可以補進已有頁面。** 啟用背景處理與指定模型後，Wenlan 會依共同實體或語義相似度，為符合條件的新記憶尋找同一 Space 裡的生成頁面，再結合原有依據與新記憶更新內容及引用。這項自動補充會跳過你建立、編輯過或鎖定審核的頁面；找不到合適頁面時，這一步不會更新頁面。

### 依據如何帶動頁面更新

Wenlan 記錄各頁所引用的來源與記憶。已追蹤的依據在 Wenlan 裡變動時，相關頁面會被標記為待更新，先前的引用檢查結果也會清除。外部檔案的變更須先透過來源重新整理讀入 Wenlan。

背景處理與指定模型可用時，刷新會依目前依據產生草稿，再檢查其中的編號引用。未通過就保留原頁面；通過後，依下方的頁面歸屬與審核規則處理。同一筆依據可能影響多個頁面，各頁分別處理。來源與記憶仍能直接檢索，不必先有頁面。

檢查會比對帶引用的句子，或其所在段落，與提供的來源文字。這是文字重合度檢查，不是事實或邏輯證明，也不會檢查每句沒有引用的敘述。[引用檢查的範圍與限制](citation-checks.zh-Hant.md)。

## 什麼時候執行

| 事件 | 會發生什麼 |
|---|---|
| 匯入資料或保存記憶 | 符合條件且尚未完成的工作進入背景處理，包括分類、資訊擷取、關聯與已設定的頁面合成。 |
| Wenlan 裡被引用的來源或記憶變更、被取代或移除 | 相關頁面被標記為待更新。外部檔案的變更須先透過該來源的重新整理方式讀入 Wenlan。 |
| 背景處理已開啟，且指定模型可用 | 本地服務依排程與資源限制分批處理；保存不代表立即刷新頁面。 |
| 背景處理關閉或指定模型不可用 | 對應的模型工作不會執行；已有資料仍可閱讀、編輯與檢索。 |

背景整理與頁面合成分別指定模型，設定其中一項不代表另一項也能執行。

## 哪些自動更新，哪些等待審核？

以下是**背景刷新知識頁**的規則，不代表所有編輯或依目標整理行為：

| 頁面狀態 | 處理結果 |
|---|---|
| AI 維護、你尚未編輯，且未開啟審核鎖定 | 有效的更新可直接套用。 |
| 你建立或編輯過 | 變更成為待審修訂，目前的頁面內容保留。 |
| 已開啟審核鎖定 | 機器修改都需核准，包括你主動請 AI 做的修改。 |
| 草稿未通過引用支持檢查 | 不套用草稿，保留目前頁面。 |

每張待審修訂只套用到它標示的頁面，不會一次核准所有受同一來源影響的頁面。你可以查看差異，再核准或略過。先前的變更仍可透過歷史紀錄查看。

## 依照目標整理既有知識

你請沉澱整理既有知識時，它會先讀取你的要求與相關資料，再只更新目標需要的內容：

- 只保存一次已確認的新發現。更正沿用既有 `supersedes` 流程；待審更正仍維持待審。
- 依需要更新或建立筆記內容、計畫與導覽，同時保留筆記 ID、來源、Space 與版本檢查。計畫仍是計畫；沒有證據時不宣稱某項行動已完成。
- 有助導覽時才建立資料夾或移動筆記。資料夾名稱本身不能證明主題或語義關係。
- 只有內容支持明確身分時，才重用或建立主題／實體。
- 只依目前有效的來源建立關係。相同事實不重複寫入；有衝突時走既有受保護的修正與審核流程。
- 回讀修改後的內容、解析出的連結、位置與語義狀態，回報已完成、待處理、受阻或未檢查項目；再次執行時略過沒變的內容。

依目標整理會依完整要求處理可存取範圍，即使目前沒有背景工作在等候。每種模式不會一律掃描或改動所有資料；一般整理也不需額外確認計畫。刪除及受保護的修正仍遵守原有控制。

Standard MCP 設定中的資料夾建立與筆記移動使用本機 stdio 操作。連線鎖定時無法建立不屬於自己的資料夾。`create_relation` 的保留操作使用 `/api/memory/relations/preserve`：來源必須仍有效，predicate 必須已識別，不允許覆蓋現有衝突或復活已退役關係；重試相同三元組會保留原有證據。舊版 daemon 會拒絕此操作。資料夾位置是導覽資訊，不能作為語義關係的證據。

除非使用者要求，其他工作流程的筆記內容保持不變。同一 Space 內目標不明確時會停止處理；不同 Space 的同名筆記會以限定連結並檢查解析後的 ID。筆記狀態本身不能證明已發佈或達成特定結果。

**主動編輯的規則不同：** 連接的 AI 若已讀取目前頁面，並提交符合當前版本的修改，可直接更新未鎖定審核的頁面。你的手動編輯不進入待審佇列。明確要求強制重新產生時，可以替換你編輯過的生成頁面；自行撰寫的頁面仍需審核。[完整更新與歷史說明](knowledge-guide.zh-Hant.md#updates-and-history)。

## 啟用沉澱與檢查結果

在設定的「沉澱」裡選一種方式：

- **隨叫**（新安裝預設）不需要背景模型。AI 工具會處理你提出的整理目標，也能處理新素材與待更新筆記。執行 `/wenlan steep`（Codex 中為 `$wenlan steep`）可接手符合條件的新素材與待更新筆記。
- **自動**會在電腦閒置時，以已設定的模型處理符合條件的背景補充、合成與頁面更新。將 AI 服務指派給背景整理或頁面合成；此模式不會自行執行未提出的重整目標。

逐句核對來源目前只在自動模式進行；隨叫時，筆記標「未驗證」。

使用自動模式時，可選透過 llama.cpp 執行的裝置端 Qwen、Ollama 或 LM Studio 等 OpenAI 相容本地服務，或支援的雲端供應商。遠端供應商會收到執行該工作所需的內容。[模型選擇與隱私](setup-and-data.zh-Hant.md#models)。

也可透過 CLI：

```bash
wenlan steep configure --help  # 選擇各項工作使用的模型來源
wenlan steep status           # 查看各項工作的關閉、就緒或暫停狀態
wenlan steep disable          # 關閉模型背景工作，保留供應商設定
```

在 Activity（活動）查看處理狀態，並透過受影響頁面的修訂與歷史畫面檢查改動。頁面尚未更新時，可確認來源變動是否已讀入 Wenlan、指定模型是否就緒，或是否有修訂等待審核。

## 為什麼值得提前整理？

可重用的記憶與帶引用頁面，有機會減少反覆蒐集脈絡及重讀原始資料。本地模型也能承擔背景工作，不必為這部分支付逐次雲端 API 費用。實際效果取決於資料、模型與任務；沉澱不保證總成本更低、回覆更快或答案更準。

實作參考：[背景排程](../crates/wenlan-server/src/scheduler.rs)、[新記憶補入頁面](../crates/wenlan-core/src/post_ingest.rs)、[實體比對](../crates/wenlan-core/src/post_write/entity_graph.rs)、[頁面合成與刷新](../crates/wenlan-core/src/synthesis/distill.rs)、[頁面歸屬與審核規則](../crates/wenlan-core/src/post_write/page_update.rs)。

## 隔離驗收範圍

整合後的流程以獨立 daemon、資料庫和頁面目錄驗收。兩個全新代理對話都只載入入口、沉澱與既有知識重整說明：第一輪保留原有 11 頁、新增 3 頁並完成 8 次移動；第二輪只讀取，頁面 ID、內容和版本完全不變。資料夾到首頁、品牌頁與規劃頁的瀏覽器導航也已檢查。這次沒有驗證原生 Tauri、背景自動模式或模型驅動的強制重建；[重現方法與完整範圍](steep.md#isolated-workflow-acceptance)。

整合 `main` 的 `35efea38` 後，另以全新資料重跑：48 次 MCP 呼叫，保留 11 頁、新增 3 頁、完成 8 次移動，讀回通過；瀏覽器檢查發現既有編輯器的表格連結只顯示標籤，因此補上入口導航必須使用段落或清單連結的規則，全新對話以 27 次 MCP 呼叫只更新品牌入口頁，隨後在瀏覽器實際點開 Reddit、Show HN、Product Hunt 三個規劃頁，全數通過且無頁面錯誤。另測試「移動後再更新內容」，確認新檔案與讀回一致、舊路徑消失、頁面 ID 與 Space 保留；整合後的路由清單、關係保護與真實 router 測試也通過。

導航修正後再以全新對話重跑：23 次唯讀 MCP 呼叫、零修改；包含獨立探針頁在內的 15 頁，其 ID、內容與版本全部不變。
