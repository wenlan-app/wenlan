## 0. 一句話

AI 做事時自動留進度，沒留到 Wenlan 幫忙補；下一個對話和人都看同一份。

## 1. 流程

```
你在做事（Claude Code／Codex／雲端）
  │
  ├─ 上下文到 8 成，或你說「交接」
  │     → 正在做事的 AI 寫那件事的那一行
  │
  └─ 沒交接就停了（閒置 50 分鐘）
        → Wenlan 拿「上次交接＋之後的對話」補一行，標「Wenlan 補的」
  ▼
Space 的「現在到哪」：一份，一件事一行
  狀態：進行中／之後再做／卡住／做完
  │
  ├─ 人：Space 頁面，每件一句
  ├─ 下一個對話：開工自動帶出每件一句與編號，要細節再拿
  └─ CLI、MCP：同一份
```

## 2. 架構

```
Claude Code / Codex / 雲端
   │  8 成提醒（掛勾） ＋ 一個「交接」動作
   ▼
Wenlan（使用者電腦）──「現在到哪」
   ▲                  ├→ App 的 Space 頁
   │讀對話紀錄          ├→ CLI
   │（用來補那行）      └→ MCP
雲端連不上：先寫交接檔到專案資料夾，連上再自動匯入
```

## 3. 兩條規則

### 規則 1：AI 自己交接

- **時機**：上下文用量過 8 成時，每輪結束的掛勾提醒 AI 交接一次（每段對話過線只提醒一次）；或人說「交接」。
- **為什麼 8 成**：有預設值的自動交接工具最常見是 80%（pi-auto-handoff、pi-handoff、claude-code-handoff；marcj/handover 建議約 80%）。Claude Code 自己約在 83% 壓縮（issue #31806，讀程式得出，非官方），8 成剛好在它之前。沒有人公開實測過最佳值；之後用我們自己的使用紀錄調。
- **怎麼偵測**：每輪結束的掛勾從對話檔（`transcript_path`）算已用比例：最後一次回覆的 token 用量 ÷ 該模型的上下文上限（依模型編號判斷，含 1M 版本；判斷不了就不提醒）。註：`used_percentage` 只在狀態列有，掛勾輸入沒有（2.1.329 程式確認，11-21 Mac 實作時發現）。Codex 同理，其對話檔直接記了上限。只有掛勾能在那時叫 AI。沒有掛勾的工具（Cursor、ChatGPT 等）偵測不到，只靠人說「交接」與規則 2。
- **不用壓縮前掛勾（PreCompact）**：它是一支程式，叫不動 AI 寫一輪；只能擋壓縮（滿了照樣壓）或交代摘要留什麼。社群工具也都不用它（392fyc/claude-handoff 明講不用）。
- **寫的是正在做事的那個 AI**，細節還在的時候寫。

### 規則 2：沒交接到，Wenlan 補

- **時機**：對話停了、沒有比它新的交接。閒置 **50 分鐘**算停（Qi-Xuan 11-21 01:56Z 同意；依據 §6）。
- **怎麼補**：Wenlan 用「那件事上次的交接＋之後的對話」寫成新的一行，標「Wenlan 補的」。Wenlan 本來就讀本機對話紀錄（`db/intake.rs`），沿用。
- **不蓋掉交接**：AI 下次正式交接就換掉這行；補的那行不算 AI 確認過。
- 對話紀錄只在本機，所以只補得到這台電腦上的對話；雲端對話靠規則 1 與交接檔。

## 4. 一份交接長什麼樣

- **一個 Space 一份**，是整個 Space 的快照。**一件事一行，不是一個對話一行**：多個對話做同一件事 → 同一行，後交接的更新；一個對話做兩件事 → 更新兩行。
- **狀態沿用 Brief 現有的**（`wenlan-types/src/brief.rs`）：進行中（active）／之後再做（backlog）／卡住（gate，寫等什麼）／做完（Complete，移出清單、歷史保留）。
- **每行兩欄**：給人的一句；給 AI 的細節（目標／決定與根據／試過不行的／還沒驗證的／下一步）。人只看一句，AI 開工只拿每件一句與編號，接手哪件再拿那件的細節。
- **存法**：每行是一筆有版本的 Brief 條目，連到它那件事（`things.brief_item_id` 已存在）。同時改同一件 → 回衝突，不蓋掉；同一操作重送只算一次。
- 首頁照舊不放交接來的事（`things.rs:756-759`）。

## 6. 閒置 50 分鐘的依據（已定案）

查到的都是 45–55 分鐘，而且都是跟著一小時的提示快取走：obie/auto-handoff、technicalpickles/auto-handoff 50 分鐘；Digitizers/agent-skills 45 分鐘；Claude Code 自己的閒置壓縮約 54 分鐘（v2.1.299 起，對話 ≥20 萬 token 才會）。建議 50 分鐘。

原則：每個工具在使用者面前講的都是同一件事（「AI 會自動交接」）只在真的做得到的工具上說；做不到的工具，Space 頁只顯示它最後一次交接，不假裝有自動。

## 7. 不在這次

- 交接不寫記憶、不碰各工具記憶；記憶（含工具記憶過時）之後另談。
- 閒置時叫回原對話寫交接、壓縮前後掛勾、指到對話哪一段：先不做。
- relay 暫存：之後。
- **交接時順便更新的其他東西**（舊 `/handoff` 技能的另外幾步：存記憶、寫對話紀錄檔、更新這段對話用過的頁面與其出處確認）：另外討論。在那邊定案前，**舊技能裡「更新用過的頁面」這一步不拿掉**，S4 拿掉三個技能要等那邊有替代。
