## 0. 一句話

每個 Space 一份「現在到哪」。任何工具用同一個 `handoff` 動作更新它；下一個 AI 開工時自動拿到；人打開 Space 就看到最新的。存不進去時，交接不會消失：給一份可以帶走的交接，之後一個指令補進去。

```
AI 收工 ──handoff──> 現在到哪 (一份，有版本)
  存不進去 ──> 可帶走的交接檔 ──之後補進去──┘
                              │
下一個 AI 開工 <── 自動帶出 ───┤
人打開 Space <── 最新那版 ─────┘
```

## 1. 審查後最大的發現（這才是「總是失敗」的主因）

1. **雲端就算 Mac 開著也寫不進去。** relay 只放行讀（`brief`、`recall`、`get_page_sources`），寫入名單裡沒有 `update_brief`。所以雲端交接不是偶爾失敗，是一定失敗。
2. **離線補送有 bug。** 補送時會換成「現在的版本號」，昨天的離線摘要可以蓋掉今天的；送到了但回應丟了，重送會被當成不同的請求拒絕。
3. **Space 頁可能顯示舊的摘要。** 晚上整理的人話版沒有對版本；頁面查一次就不再更新；團隊成員的網頁版讀不到這兩個端點（`src/web/team.ts:44`）。

這三個是現有的 bug，先修，再談新功能。

## 2. 誰讀、何時、在哪（不變）

| 讀的人 | 何時 | 在哪 | 需要什麼 |
|---|---|---|---|
| 下一個接手的 AI（主要） | 開工第一句之前 | Claude Code、Codex、其他 MCP 工具、雲端對話 | 做到哪一兩句、進行中每件一行、卡在誰、下一步 |
| 人 | 想知道進度時 | app 的 Space 頁最上面 | 最新那版、誰交接的、多久前 |
| 同時在做事的其他 AI | 做到一半 | 同上 | 別人剛改了哪條，自己的不被蓋掉 |

首頁「正在做」只放對話讀出的事（UX-HOME-6），不變。

## 3. 和各工具原生記憶的分工（新增）

依 11-11 定的設計、#1261 已上線：
- 原生記憶（Claude Code、Codex 的記憶檔）= 知識。Wenlan 每小時唯讀跟一次，只收新的、有用的知識；習慣、過時、敏感、**工作進度**不收。
- 「現在到哪」= 進度。只在 Wenlan 一處。
- **交接不寫進任何工具的記憶檔**，也不寫進 AGENTS.md（進度會讓 repo 一直變動）。下一個工具拿到交接，是靠開工帶出和 `brief`，不是靠它自己的記憶。
- 各工具的 resume 只在同一個工具內有效；Wenlan 管換工具、換人、換電腦。

## 4. 不變成垃圾堆（新增，回應 Pieces 的抱怨）

- 一個 Space 一份，原地更新；做完的關掉，不留在畫面上。
- 對話紀錄不複製，讀工具原本存的地方。
- 交接不另存記憶、不寫新頁（頁面更新是另一件事，不綁在交接上）。
- 進行中有上限（建議 20 條），超過時交接回收據提醒「先關掉幾條」，不默默丟。
- 歷史保留，但只存差異，不存整份副本。

## 5. 目標體驗

**人**：什麼都不用做。Space 頁看到最新的「現在到哪」和「上次交接：Codex，5 分鐘前」。交接成功不打擾；沒存到時，在對話裡說清楚是哪一種：已排隊、已存在本專案、或「請把這段帶到下一個對話」。

**AI 開工**：Claude Code 和 Codex 開場時自動拿到「現在到哪」（兩者都有開場 hook；Codex 0.170 已穩定支援，Mac 上已啟用）。其他 MCP 工具只能「可用」，不能保證會讀，不對使用者這樣承諾。

**AI 收工**：一個動作 `handoff`。AI 交這次的結果；對已有的條目，用開工時拿到的編號改；沒編號的就是新增。Wenlan 不靠文字猜是哪一條。

**重複**：
- 同一次交接重送（網路斷、回應丟）：完全一樣的內容、同一個編號，只算一次，結果相同。
- 第二次交接：改的是有編號的那幾條，沒提到的保持不動。
- 兩邊同時改同一條：先到的生效；後到的若是根據舊版本改的，**不蓋掉**，回傳「衝突」，其他不相干的照樣生效。AI 收到衝突，重讀再決定。不默默「新的贏」。

**忘了**：見 §7，分兩步，先做便宜可靠的那步。

**連不上**：見 §8。

## 6. 規則（每條以「下一個讀的人看到什麼」來驗收）

| id | 規則 | 驗收 |
|---|---|---|
| UX-HAND-1 | 每個 Space 一份「現在到哪」，有版本；app、CLI、MCP 讀到同一版。人話版只在對應目前版本時才顯示，否則顯示原文。 | 交接後，app、`wenlan brief`、MCP `brief` 回同一個版本號；人話版版本落後時 app 顯示原文 |
| UX-HAND-2 | 一個動作 `handoff`（HTTP、CLI、MCP 同一份請求）。有編號的條目必須帶看到的版本；沒編號的是新增；沒提到的不動。 | 第二個對話讀到第一個對話的卡點與下一步，且另一人的條目原封不動 |

| UX-HAND-5 | Claude Code 與 Codex 開場自動帶出這個 Space 的「現在到哪」（短版、有總時限、Wenlan 沒開就略過）。 | 開場的模型上下文含交接內容；第一句回覆用到它（兩項分開測） |

| UX-HAND-11 | 不變垃圾堆：交接不另存記憶、不寫頁；進行中上限 20 條，超過時提醒，不默默丟。 | 連續交接 50 次，條目數只跟實際新增有關，資料量線性於差異 |

## 7. 忘了交接（分兩步）

**第一步（v1，不用模型、不讀對話內容）**：Claude Code 與 Codex 在壓縮前、正常結束時，送一個很小的「檢查點」：哪個對話、哪個 Space、最後活動時間。同一個對話只留最新一個。若之後沒有正式交接，**下一個 AI 開工時**會看到一行「上一個對話（Codex，昨天 18:00）沒有交接」，由它決定要不要先問人或補。正式交接永遠優先。

**第二步（之後，要明確打開）**：從對話紀錄自動補寫。條件：背景 AI 有開、對話只屬於一個 Space、該 Space 是個人的、Wenlan 自己確認過對話身份並在工具已知的資料夾裡找到紀錄。混了多個 Space 或任何團隊 Space 的，一律不補。要等第一步上線、看到真的有漏才做。

## 9. 分批

1. **S0 修 bug**：outbox 補送（UX-HAND-4）、Space 頁舊摘要與不更新、團隊網頁讀不到（UX-HAND-1、9）。
2. **S1 一個動作**：`handoff` + 版本與衝突（UX-HAND-2、3、11），雲端在線可寫（UX-HAND-6）。
3. **S2 開工帶出**：Claude Code + Codex 開場 hook（UX-HAND-5）。
4. **S3 帶得走**：離線交接與 `--file`（UX-HAND-7、8），檢查點（§7 第一步）。
5. **S4 收尾**：名字（UX-HAND-13）、團隊私密測試（UX-HAND-10）。
6. **之後**：自動補寫（§7 第二步）、relay 暫存。

## 10. 刪掉的（v1 有、v2 不做）

- 用文字相同或同一對話來合併條目；默默「新的贏」。
- 預設的自動摘要組合（壓縮前、結束、每晚、第一句補寫同時跑）。
- relay 存交接內容、專案資料夾自動匯入器。
- 技能合併成一份（其實已經由同一個來源產生，CI 有檢查；v1 說法錯了）、`_status` 改寫、技能 40 行目標、交接時強制更新頁面。
