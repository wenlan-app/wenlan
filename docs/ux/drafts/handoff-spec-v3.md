## 0. 一句話

每個 Space 一份「現在到哪」。正在做事的 AI 一邊做一邊自動更新它（人不用叫），任何工具都用同一個 `handoff` 動作；下一個 AI 開工時自動拿到；人打開 Space 就看到最新的。存不進去時，交接不會消失：給一份可以帶走的交接，之後一個指令補進去。

```
AI 做事中 ──自動交接──> 現在到哪 (一份，有版本)
  存不進去 ──> 可帶走的交接檔 ──之後補進去──┘
                              │
下一個 AI 開工 <── 自動帶出 ───┤
人打開 Space <── 最新那版 ─────┘
```

## 1. 審查後最大的發現（這才是「總是失敗」的主因）

1. **雲端就算 Mac 開著也寫不進去。** relay 只放行讀（`brief`、`recall`、`get_page_sources`），寫入名單裡沒有 `update_brief`。所以雲端交接不是偶爾失敗，是一定失敗。
2. **離線補送有 bug。** 補送時會換成「現在的版本號」，昨天的離線摘要可以蓋掉今天的；送到了但回應丟了，重送會被當成不同的請求拒絕。
3. **Space 頁可能顯示舊的摘要。** 晚上整理的人話版沒有對版本；頁面查一次就不再更新；團隊成員的網頁版讀不到這兩個端點（`src/web/team.ts:44`）。

這三個是現有的 bug，先修，再談新功能。

## 2. 誰讀、何時、在哪（不變）

| 讀的人 | 何時 | 在哪 | 需要什麼 |
|---|---|---|---|
| 下一個接手的 AI（主要） | 開工第一句之前 | Claude Code、Codex、其他 MCP 工具、雲端對話 | 做到哪一兩句、進行中每件一行、卡在誰、下一步 |
| 人 | 想知道進度時 | app 的 Space 頁最上面 | 最新那版、誰交接的、多久前 |
| 同時在做事的其他 AI | 做到一半 | 同上 | 別人剛改了哪條，自己的不被蓋掉 |

首頁「正在做」只放對話讀出的事（UX-HOME-6），不變。

## 3. 和各工具原生記憶的分工（新增）

依 11-11 定的設計、#1261 已上線：
- 原生記憶（Claude Code、Codex 的記憶檔）= 知識。Wenlan 每小時唯讀跟一次，只收新的、有用的知識；習慣、過時、敏感、**工作進度**不收。
- 「現在到哪」= 進度。只在 Wenlan 一處。
- **交接不寫進任何工具的記憶檔**，也不寫進 AGENTS.md（進度會讓 repo 一直變動）。下一個工具拿到交接，是靠開工帶出和 `brief`，不是靠它自己的記憶。
- 各工具的 resume 只在同一個工具內有效；Wenlan 管換工具、換人、換電腦。

## 4. 不變成垃圾堆（新增，回應 Pieces 的抱怨）

- 一個 Space 一份，原地更新；做完的關掉，不留在畫面上。
- 對話紀錄不複製，讀工具原本存的地方。
- 交接不另存記憶、不寫新頁（頁面更新是另一件事，不綁在交接上）。
- 進行中有上限（建議 20 條），超過時交接回收據提醒「先關掉幾條」，不默默丟。
- 歷史保留，但只存差異，不存整份副本。

## 5. 目標體驗

**人**：什麼都不用做。Space 頁看到最新的「現在到哪」和「上次交接：Codex，5 分鐘前」。交接成功不打擾；沒存到時，在對話裡說清楚是哪一種：已排隊、已存在本專案、或「請把這段帶到下一個對話」。

**AI 開工**：Claude Code 和 Codex 開場時自動拿到「現在到哪」（兩者都有開場 hook；Codex 0.170 已穩定支援，Mac 上已啟用）。其他 MCP 工具只能「可用」，不能保證會讀，不對使用者這樣承諾。

**AI 收工**：一個動作 `handoff`。AI 交這次的結果；對已有的條目，用開工時拿到的編號改；沒編號的就是新增。Wenlan 不靠文字猜是哪一條。

**重複**：
- 同一次交接重送（網路斷、回應丟）：完全一樣的內容、同一個編號，只算一次，結果相同。
- 第二次交接：改的是有編號的那幾條，沒提到的保持不動。
- 兩邊同時改同一條：先到的生效；後到的若是根據舊版本改的，**不蓋掉**，回傳「衝突」，其他不相干的照樣生效。AI 收到衝突，重讀再決定。不默默「新的贏」。

**自動交接（預設開）**：寫交接的是正在做事的那個 AI，時機由 Wenlan 叫它，人不用叫。見 §7。

**連不上**：見 §8。

## 7. 自動交接（v3 改寫：Qi-Xuan 20:43Z「我以為體驗是會自動交接？」）

原則：**寫交接的永遠是正在做事的那個 AI**，不是背景模型。它最清楚做了什麼、用的是使用者本來的模型、Space 跟著它的工作資料夾（現有解析），不用猜。Wenlan 只決定「什麼時候叫它」。

```
每輪結束 ─Wenlan 看─> 上次交接後有新工作 且
                      (距上次交接 ≥20 分鐘 或 對話快滿)
                       └─> 叫 AI 安靜更新一次 ✓
對話開著沒動 ─> 沒新工作，不用做
下一個 AI 在同一 Space 開工 ─> 其他對話(開著或關掉)
   有沒交接的工作 ─> 先替它補上 ✓
人叫 /handoff ─> 馬上做
```

- **觸發**：Claude Code 與 Codex 的「每輪結束」掛勾（Stop）問 Wenlan：這個對話上次交接後有沒有新的工作、且距上次交接已滿 20 分鐘（數字可調）或對話已接近上限。不判斷「做完沒有」（Qi-Xuan 20:45Z「怎麼轉到做完一段啦？如果沒有明確結束或關掉」）。是的話，掛勾要求 AI 再做一步：呼叫 `handoff`，不回覆使用者。每次交接是改條目不是另寫一份，所以頻繁不會堆積；Wenlan 沒開或 1 秒內沒回就略過，不卡對話。
- **待驗證**：Claude Code 的 Stop 掛勾可要求 AI 繼續一步（已知）；Codex 0.170 的 Stop 掛勾能否同樣要求繼續，要在實作前於 Mac 上確認，不行就退回「下一個 AI 補交接」。
- **壓縮前／正常結束**：只記一個很輕的「停在這裡」記號（對話、Space、最後活動時間），不叫模型、不讀內容。同一對話只留最新一個。
- **漏掉的補交接**：下一個 AI 在同一個 Space 開工時，若看到同一 Space 的其他對話（開著或已關都算）在最後一次交接後還有工作，先讀那個對話在本機工具資料夾裡的紀錄（只限 Wenlan 自己確認過的對話身份與已知資料夾，不接受外部指定路徑），替它補交接，標「補交接」，然後才開始自己的工作。只補同一個 Space、同一台電腦的對話。
- **一份為準**：同一段工作，正式交接（人叫的或 AI 被叫的）只有一份；補交接只在沒有正式交接時發生；兩者都用編號＋版本（UX-HAND-2、3），不會互蓋。
- **不另跑背景模型**：v3 不做「晚上由背景模型讀對話補寫」。若之後證明仍有漏，再評估，且只限個人 Space。
- **團隊 Space**：自動交接與補交接都照 UX-HAND-10，私人對話來的文字不進共享 Space。

## 10. 刪掉的（v1 有、v2 不做）

- 用文字相同或同一對話來合併條目；默默「新的贏」。
- 背景模型從對話紀錄補寫（壓縮前、結束、每晚同時跑）。改成：正在做事的 AI 自己交接（§7）。
- relay 存交接內容、專案資料夾自動匯入器。
- 技能合併成一份（其實已經由同一個來源產生，CI 有檢查；v1 說法錯了）、`_status` 改寫、技能 40 行目標、交接時強制更新頁面。
