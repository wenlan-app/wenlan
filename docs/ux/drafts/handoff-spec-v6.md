## 0. 一句話

一個 Space 一份交接，裡面每件進行中的事各一句「現在到哪」。正在做事的 AI 在對話壓縮時自動更新它那件事；對話停了沒交接，顯示 Wenlan 從對話讀到的那句並標明；下一段對話（不論同工具、別的工具或別人）開工時自動拿到；人打開 Space 就看到最新的。人不用打任何指令。

```
對話壓縮 ─> AI 更新它那件事那一句 ✓
對話停了沒交接 ─> 顯示「從對話讀到的」那句 ✓
下一段對話開工 <── 自動帶出 (每件一句)，開口後再拿那件的細節
人打開 Space <── 每件一句，最新的
存不進去 ─> 可帶走的交接檔 ─> 之後補進去
```

## 2. 誰讀、何時、在哪

交接是給**下一段對話**的；壓縮摘要只給同一段對話自己。AI 只記得同一段對話裡的內容，新對話從空白開始，所以跨對話一定要寫在對話之外（Anthropic〈Effective harnesses for long-running agents〉："compaction isn't sufficient"）。

| 讀的人 | 何時 | 在哪 | 需要什麼 |
|---|---|---|---|
| 下一段對話的 AI（主要；最常見是同一工具明天的新對話） | 開工第一句之前 | Claude Code、Codex；其他工具靠 `brief` | 每件事一句；接手那件的細節 |
| 人 | 想知道進度時 | app 的 Space 頁最上面 | 每件事一句、誰、多久前 |
| 同時在做事的其他對話 | 做到一半 | 同上 | 別件事的現況，自己那件不被蓋掉 |

## 3. 資料模型：Space → 事 → 對話（v5 依 Fable #1、#2 改）

- **對話**：原始出處，一定要有。
- **事**（UX-THING-1）：一條工作線，可跨對話、工具，也可跨 Space（`docs/ux/spec.md` Words）。目前 `things` 表沒有 Space、擁有者或版本欄位（`crates/wenlan-core/src/db/things.rs:31-39`），現況句 `thing_lines` 也沒有版本（`db/intake.rs:41-45`），而且只在本機、背景 AI 開著時才產生。
- **每一句「現在到哪」存成 Space 的 Brief 條目**（已有 Space、版本、歷史），並連到它那件事：`things.brief_item_id` 已經存在（`things.rs:35`），沿用並補上反向連結。對人來說仍是「一份交接、每件事一句」（Qi-Xuan 22:43Z 決定的體驗不變），只是存法用 Brief 條目，不另建。
- **每句兩個欄位**：給人看的一句人話（夜間整理照 UX-SPACE-2 寫）；給 AI 的交接內容（目標／決定與根據／試過不行的／還沒驗證的／下一步）。
- **誰能寫**：交接（帶版本）優先。Wenlan 從對話讀到的現況，只在那件事沒有比它新的交接時才顯示，並標「從對話讀到，未交接」，不覆蓋交接（Fable #2：分組每 10 分鐘跑一次，若同寫一句會蓋掉剛交接的）。
- **一件事一行，不是一個對話一行**：多個對話做同一件事 → 同一行，後交接的更新；一個對話做兩件事 → 更新兩行。
- **分類沿用 Brief 現有狀態**（`wenlan-types/src/brief.rs`）：進行中（active）／之後再做（backlog）／卡住（gate，寫等什麼）／做完（Complete，移出清單、歷史保留）。交接只設狀態，不另建分類。頁面先列進行中，之後再做收起。
- **新對話的歸屬**：開工時還不知道接哪件事。交接沒帶編號時，以對話編號為準：同一段對話的交接都歸同一條，避免交接開一條、分組又開一條（Fable #3）。
- 首頁照舊只放「我的事」，從交接來的不放首頁（`things.rs:756-759` 現有規則，11-06 因首頁塞滿 AI 工作紀錄而定）。要改寫的規則：UX-HOME-6、Words 的「事」定義、UX-SPACE-1。
- 壓縮摘要原文**只留本機**，不送團隊 Space、不經 relay（Fable：隱私與提示注入）；別人看到的只有 AI 寫的交接欄位。
- 與主流的差別：主流一個 repo（或分支）一份交接檔，同時兩件事會互蓋或要人找；Wenlan 一份交接、每句各自更新、自動、跨工具、人看得到。

## 4. 和各工具自己記憶的分工

1. 一個教訓或決定只有一個原始出處：那段對話。工具自己的記憶、Wenlan 從對話讀到的，都是轉述；Wenlan 存「那件事」一筆，多掛出處（沿用 11-11 設計、#1261）。
2. **交接一律不存記憶**（已決定，Qi-Xuan 22:33Z）。教訓走「唯讀跟著工具記憶」與「對話讀取」兩條路。代價：Wenlan 讀不到的雲端記憶（claude.ai、ChatGPT）裡的教訓不會經由交接進來。
3. Wenlan 不寫回任何工具的記憶檔，也不把進度寫進 AGENTS.md。
4. 規則送回各工具走既有的路：接了 repo 的 Space 經 PR 進 AGENTS.md（UX-SKILL-7）；所有 Space 共用的進各工具規則檔（UX-SKILL-8）；沒接 repo 的 Space 規則由 AI 透過 `read_space_rules` 查（維持現狀）。
5. 進度不是記憶，只放「現在到哪」。

**工具記憶過時（定案，Qi-Xuan 11-21 00:30Z）**：不改會誤導人。業界沒有記憶工具去改別家工具的記憶（Claude Code 官方要使用者自己定期清；Mem0、Zep 只管自己那份，覆蓋或標過期）。做法：
- Wenlan 仍不直接寫別家的檔案（避免兩個寫入者互打）。
- 新對話開工時，若該工具記憶裡某條與 Wenlan 較新的決定相反，開工內容帶一句「你記憶裡 X 已過時，現在是 Y（出處）」，由**那個工具的 AI 自己改自己的記憶**（Claude Code 的自動記憶本來就由它寫）。改了跟人說一行。
- Wenlan 自己那份把舊的標成「已被取代」，不刪，歷史保留。
- Codex 記憶能否由它自己改：S2 前實測。讀不到的雲端記憶（claude.ai、ChatGPT）不處理。

## 5. 不變成垃圾堆

- 每件事一句，原地更新；做完的關掉，離開畫面。
- 對話紀錄不複製；每段對話只留最新一份摘要。
- 交接不存記憶、不寫頁。
- 被取代且久未被讀的淡出（不刪，歷史可查）。門檻實作時訂。
- 開工帶出上限約 2000 token（參考 agentmemory 預設），只帶每件一句與編號；細節等 AI 知道接哪件後用 `brief` 拿。
- 不設件數上限（UX-HOME-5 定了「不設上限、不猜做完沒」）。

## 6. 自動交接（v5 依 Fable #4、#5 改）

原則：**寫交接的是正在做事的那個 AI**，Space 跟著它的工作資料夾，Wenlan 只決定時機。

| 時機 | 做什麼 | 依據 |
|---|---|---|
| 對話壓縮 | `PostCompact` 掛勾拿到 `compact_summary`，存成這段對話最新摘要（只本機）；子代理（帶 `agentId`）的壓縮不算 | 已在 Claude Code 2.1.329 確認此欄位；PostCompact 的輸出只給人看，不能叫 AI 做事 |
| 壓縮後 | `SessionStart`（來源 `compact`）用 `additionalContext` 放回「現在到哪」，並請 AI 第一步呼叫 `handoff` 更新它那件事 | 已確認 SessionStart 支援 `additionalContext` 且有 `compact` 來源 |
| 上下文快滿 | **定案**：每輪結束的掛勾讀這段對話已用的上下文（Claude Code 有算好的已用百分比 `used_percentage`），過 7 成時提醒 AI 交接一次；每段對話過線一次只提醒一次。不用固定 30 分鐘 | 業界主流看上下文用量（7–9 成）或閒置；只有掛勾能在那時叫 AI，AI 自己估不準。沒有掛勾的工具無法偵測 |
| 突然塞滿、來不及到 7 成就壓縮 | 由下一列「壓縮後」接住：壓縮完第一輪就交接 | 兩道網：7 成提醒＋壓縮後交接 |
| 停了沒交接、閒置 | **定案**：不叫別的 AI 代寫。閒置時 AI 沒在跑，無法叫它交接；Wenlan 看對話檔，**30 分鐘沒有新訊息**就更新「從對話讀到」那句（沿用 `db/intake.rs:50` 現有 30 分鐘），當成那件事的進度，標「從對話讀到，未交接」，並記下出自對話哪一段（對話檔＋位置）。下一個 AI 只讀那段，不必從頭讀；限同一台電腦（對話紀錄只在本機）。之後有正式交接就取代它 | v4 的代補違反「由正在做事的 AI 寫」，平行對話時會替只是閒置的對話代寫，且無法穩定測試（Fable #5） |
| 人說「交接一下」 | AI 直接呼叫 `handoff` | — |

- Codex：`plugin-codex/` 目前沒有任何掛勾；開場輸出能否進到模型、有沒有壓縮後事件、rollout 摘要格式，都要在 S2 前實測。
- 雲端對話：靠它自己 `handoff` 或可帶走的交接檔。
- 讀不到壓縮摘要的工具（Cursor、Gemini 等）：靠它們用 `handoff`。

## 7. 一個動作與重複

- `handoff`（HTTP、CLI、MCP 同名同請求）：AI 交這次的結果；已有的那件事用開工時拿到的編號與版本改；沒編號的是新增的事；沒提到的不動。
- 重送：同一個操作編號只認第一次的內容，結果相同。
- 同時改同一件：根據舊版本的修改回傳衝突，不蓋掉；不相干的照樣生效。AI 收到衝突重讀再決定。
- 不靠文字相同或同一對話來合併（Astra #1）。

## 11. 分批
