## 0. 一句話

一個 Space 裡每件進行中的事各有一句「現在到哪」。正在做事的 AI 在對話壓縮時自動更新它那件事；對話停了沒交接，下一個 AI 先替它補；下一段對話（不論同工具、別的工具或別人）開工時自動拿到；人打開 Space 就看到最新的。人不用打任何指令。

```
對話壓縮 ─> AI 更新它那件事那一句 ✓
對話停了沒交接 ─> 下一個 AI 先補 ✓
下一段對話開工 <── 自動帶出 (每件一句 + 接手那件的細節)
人打開 Space <── 每件一句，最新的
存不進去 ─> 可帶走的交接檔 ─> 之後補進去
```

## 2. 誰讀、何時、在哪

交接是給**下一段對話**的；壓縮摘要只給同一段對話自己。AI 只記得同一段對話裡的內容，新對話從空白開始，所以跨對話一定要寫在對話之外（Anthropic〈Effective harnesses for long-running agents〉："compaction isn't sufficient"）。

| 讀的人 | 何時 | 在哪 | 需要什麼 |
|---|---|---|---|
| 下一段對話的 AI（主要；最常見是同一工具明天的新對話） | 開工第一句之前 | Claude Code、Codex；其他工具靠 `brief` | 每件事一句；接手那件的細節 |
| 人 | 想知道進度時 | app 的 Space 頁最上面 | 每件事一句、誰、多久前 |
| 同時在做事的其他對話 | 做到一半 | 同上 | 別件事的現況，自己那件不被蓋掉 |

## 3. 資料模型：Space → 事 → 對話

- **對話**：原始出處，一定要有。
- **事**（UX-THING-1）：一條工作線，可跨多段對話、多個工具。Wenlan 已從對話紀錄讀出每段對話把事情留在哪（`conversation_intake.rs` 的 `status`）與每件事的近況（`OpenThing.news`）。
- **「現在到哪」= 這個 Space 裡每件進行中的事各一句**（已決定，Qi-Xuan 22:43Z「可以」）。原本 Brief 的條目與「事」合成一套：交接只更新它那件事那一句；對話讀取也寫同一句。

```
Space
 ├─ 事 A：一句現況      ← 交接、對話讀取都寫這裡
 │   ├─ 細節：目標／決定與根據／試過不行的／還沒驗證的／下一步
 │   └─ 對話 1 (Claude Code，最新摘要)、對話 2 (Codex，最新摘要)
 └─ 事 B：一句現況
```

- 細節欄位照搬近半年業界交接檔的常見欄位（alook、Hermes、SashiDo 等，2026-07 至 11 月）。
- 一件事一句只有一份，有版本；最後做事（壓縮）的那個 AI 更新；同時改照版本處理（UX-HAND-3）。
- 每段對話只留**最新一份**壓縮摘要當細節，新的取代舊的（新摘要本身已包含舊摘要的內容）。
- 首頁照舊只放「我的事」；Space 頁放這個 Space 所有人的事。UX-HOME-6 的「Brief 條目不是一件事」要改寫。
- 與主流的差別：主流一個 repo（或分支）一份交接檔，同時兩件事會互蓋或要人找；Wenlan 每件事分開、自動、跨工具、人看得到。

## 4. 和各工具自己記憶的分工

1. 一個教訓或決定只有一個原始出處：那段對話。工具自己的記憶、Wenlan 從對話讀到的，都是轉述；Wenlan 存「那件事」一筆，多掛出處（沿用 11-11 設計、#1261）。
2. **交接一律不存記憶**（已決定，Qi-Xuan 22:33Z）。教訓走「唯讀跟著工具記憶」與「對話讀取」兩條路。代價：Wenlan 讀不到的雲端記憶（claude.ai、ChatGPT）裡的教訓不會經由交接進來。
3. Wenlan 不寫回任何工具的記憶檔，也不把進度寫進 AGENTS.md。
4. 規則送回各工具走既有的路：接了 repo 的 Space 經 PR 進 AGENTS.md（UX-SKILL-7）；所有 Space 共用的進各工具規則檔（UX-SKILL-8）；沒接 repo 的 Space 規則由 AI 透過 `read_space_rules` 查（維持現狀）。
5. 進度不是記憶，只放「現在到哪」。

**待決定**：工具自己的記憶過時、與 Wenlan 較新的決定相反時，Wenlan 改不了它。建議先不改，只在對話中提醒（UX-CHAT-1 規劃中）。

## 5. 不變成垃圾堆

- 每件事一句，原地更新；做完的關掉，離開畫面。
- 對話紀錄不複製；每段對話只留最新一份摘要。
- 交接不存記憶、不寫頁。
- 進行中上限 20 件，超過時回收據提醒，不默默丟。
- 被取代且久未被讀的淡出（不刪，歷史可查）。門檻實作時訂。
- 開工帶出上限約 2000 token（參考 agentmemory 預設），超過只帶每件一句與接手那件的細節。

## 6. 自動交接

原則：**寫交接的是正在做事的那個 AI**，Space 跟著它的工作資料夾（現有解析），Wenlan 只決定時機。

| 時機 | 做什麼 | 狀態 |
|---|---|---|
| 對話壓縮 | Claude Code `PostCompact` 掛勾拿到 `compact_summary`（已在目前 Claude Code 確認此欄位），原樣交 Wenlan 存成那段對話的最新摘要；壓縮後上下文加一行，請 AI 第一步呼叫 `handoff` 更新它那件事 | Claude Code 可行；Codex 摘要在 rollout 紀錄中，壓縮後掛勾待確認 |
| 壓縮後同一段對話 | Claude Code 以 `compact` 來源重跑開場掛勾，Wenlan 再放回「現在到哪」 | 可行 |
| 停了沒交接 | 最後一次交接後有工作、且 30 分鐘無活動（看本機對話紀錄，不靠結束事件；正常關、直接關、當掉、蓋上電腦、開著不管都一樣；resume 即解除） | 新 |
| 誰補 | 1 下一個在同一 Space 開工的 AI（同一台電腦），先讀 Wenlan 已寫好的那件事現況，不夠才讀那段對話的最新摘要或紀錄；2 沒人開工且背景 AI 有開：Wenlan 補，只限個人 Space；3 都沒有：Space 頁顯示「誰的對話停在幾點，沒交接」，團隊 Space 不放內容 | 新 |
| 人說「交接一下」 | AI 直接呼叫 `handoff` | 新 |

- 不加固定時間保底（業界多在壓縮／快滿時或閒置後寫，未見每小時固定寫；已決定 20:58Z）。已知缺口：大上下文模型可能好幾小時才壓縮，另一台電腦的隊友要等到壓縮或停下。
- 雲端對話：Wenlan 讀不到雲端紀錄，只能靠它自己 `handoff` 或可帶走的交接檔。
- 讀不到壓縮摘要的工具（Cursor、Gemini 等）：靠它們用 `handoff`，或下一個 AI 補。

## 7. 一個動作與重複

- `handoff`（HTTP、CLI、MCP 同名同請求）：AI 交這次的結果；已有的那件事用開工時拿到的編號與版本改；沒編號的是新增的事；沒提到的不動。
- 重送：同一個操作編號只認第一次的內容，結果相同。
- 同時改同一件：根據舊版本的修改回傳衝突，不蓋掉；不相干的照樣生效。AI 收到衝突重讀再決定。
- 不靠文字相同或同一對話來合併（Astra #1）。

## 11. 分批

1. **S0 修 bug**：§1 三項（UX-HAND-1、4、6、9）。
2. **S1 一個動作 + 合成一套**：`handoff`、版本與衝突、Brief 條目併入「事」（UX-HAND-2、3、11、16）。
3. **S2 開工帶出**：Claude Code、Codex 開場掛勾；`wenlan setup` 一併裝掛勾（UX-HAND-5）。
4. **S3 自動交接**：壓縮時、停了沒交接與補交接（UX-HAND-14、15、17）。
5. **S4 帶得走**：可帶走的交接檔與 `--file`（UX-HAND-7、8）。
6. **S5 精簡入口**：拿掉三個技能與兩張新手卡、`update_brief` 移出預設、名字（UX-HAND-12、13）；團隊私密測試（UX-HAND-10）。
7. **之後**：relay 暫存；背景補寫擴大（只在證明仍有漏時）。
